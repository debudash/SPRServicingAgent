SPR Servicing Desk

A multi-agent desk for withdrawals and hardship cases. Three agents read, explain and judge. Code routes every step, writes every figure and holds the authority to move money.

The desk never moves money unless identity, the shown quote, the customer's explicit confirmation and an independent compliance approval of that exact proposal are all established, and it never grants a waiver.

Edges are Python functions of the conversation state. The only model output that steers routing is the Concierge's intent, and every intent still passes the same gates. The graph does not pause for a person: the case is stored, and the reviewer decides in the review queue through the same token and ledger.

Where the authority lives

Guards are code, tested with a scripted model

Login, then step-up

A login and Gate A (the record) open the account view, shown at the top of the chat. Moving money needs the step-up form too; three failures lock the session and void the quote.

FR-02 · GR-12 · ADR 0007

Quote, yes, token, then execute

The token is an HMAC over the proposal hash. Change the amount and the token is void.

FR-08 · GR-16 to GR-18

Compliance cannot override a flag

A rule flag sends the withdrawal to a person, whatever Compliance says.

FR-11

One withdrawal per proposal

The proposal ID is unique in the ledger, so a replayed execute or a repeated yes moves nothing.

FR-09 · #140

Budgets stop runaway turns

8 hops, 12 tool calls, 30 seconds per turn. Running out ends the turn UNAVAILABLE with nothing done.

FR-20 · D-10

Fail closed

Compliance down: nothing executes. Execution switched off: a rule flag sends the withdrawal to a person, and the ledger refuses too.

Two sources of truth

Numbers from records, narrative from documents

desk.db (SQLite)

Accounts without restricted fields; identity and logins behind one module; proposals, approvals, transactions, cases; an append-only, hash-chained audit table.

PG-01 · PG-04 · PG-10

knowledge/ → Chroma

Versioned documents with an ID, version and effective date on every chunk, embedded locally with ONNX. Includes three synthetic SPR operations documents and a superseded fee schedule.

PG-05 · PG-06 · FR-24 · ADR 0006

One clock, one mask

Contract year and age derive from the as-of date. Credential-shaped text is captured for the gate and masked before any prompt, trace, log or packet.

D-04 · FR-23 · ADR 0005

Trace and audit kept apart

LangSmith can trace the model calls for debugging. The audit table answers a regulator: every deciding node writes a row with the versions in force.

Design not yet in the code

What the build changed or still owes

No graph pause

The design paused the graph with a LangGraph interrupt. The built desk stores the case and the reviewer decides outside the graph; no checkpointer is wired.

ARCHITECTURE 3.4

Cost budget not enforced

$0.10 per conversation is defined, but model cost is not yet added to it. Hops, tool calls and seconds are enforced.

FR-20 · D-10

No audit rebuild command

The audit is stored and chain-checked, but there is no single command that rebuilds a conversation and its cases yet.

FR-25

Leftover model entries

Case and the reply became code, but the model map still lists Case and Transaction, and an unused reply prompt remains.
